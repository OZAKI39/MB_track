# 微泡 / 微泡团识别与跟踪（PZT 控制实验）

本项目用于分析明场显微视频中的微泡和微泡团，研究 PZT 控制下微泡如何成团、成团后形状如何变化，以及微泡/团的位移。程序逐帧输出每个目标的位置、速度、面积和形状，并记录融合、分裂等事件。处理是因果的（不需要读后面的帧），可以实时运行。

- 不需要空白背景帧：背景直接从录像本身估计。
- 不依赖 SAM 等大模型，只用 OpenCV + NumPy + SciPy，普通电脑即可实时运行。
- 团的编号在移动、融合、分裂过程中保持稳定，谱系关系写在事件表里。

## 快速开始

### 1. 安装

需要 Python 3.8 及以上。

```bash
pip install -r requirements.txt
```

可选：安装 ffmpeg 后，叠加视频会用 H.264 编码（体积更小）；没有 ffmpeg 时自动改用 OpenCV 自带的编码器。

### 2. 复现本项目的全部结果

在项目根目录运行：

```bash
python tools/run_experiments.py            # 约 5–6 分钟，含叠加视频
python tools/run_experiments.py --no-render  # 不生成视频，约 3–4 分钟
```

### 3. 处理新的视频

```bash
# 离线分析（推荐用于出论文数据）。--ref 可以加同一次装片的其他视频或 background.npy
python bubble_tracker.py 新实验.mp4 --ref 同一装片的另一段.mp4 --out 结果目录 --render

# 实时模式：只用参考背景，不读未来帧
python bubble_tracker.py 新实验.mp4 --bg online --ref results/session_background.npy --out 结果目录
```

只想看命令行参数：`python bubble_tracker.py -h`。

## 推荐工作流程

核心前提：**注射完成后，同一次装片期间芯片不再移动，视野是静止的。** 在本项目的两段视频里，A 和 B 之间的视野偏移不到 1 个像素。

1. **装片、注射，等通道稳定。**
2. **录第一段视频。** 可以是正式实验，也可以是 5–10 秒 PZT 工作中的预热视频，只要微泡在动就行。
3. **离线跑这段视频，得到参考背景：**
   ```bash
   python bubble_tracker.py 第一段.mp4 --out 装片1_第一段
   ```
   生成的 `装片1_第一段/background.npy` 就是这次装片的参考背景。
4. **同一次装片的后续实验：**
   - 实时：`python bubble_tracker.py 第二段.mp4 --bg online --ref 装片1_第一段/background.npy --out ...`
   - 离线：`python bubble_tracker.py 第二段.mp4 --ref 第一段.mp4 --out ... --render`
   
   多段参考可以一起给（`--ref a.mp4 b.npy c.mp4`），程序会先自动对齐，再逐像素取最亮值合并。参考越多，长时间停留的团对背景的影响越小。
5. **重新装片后，从第 1 步重新开始。** 旧的参考背景不能再用。

## 方法说明

### 1. 背景估计（不需要空白帧）

明场下微泡和团都是暗的，而且大部分时间在动，所以同一个像素在大多数时间里看到的是背景。

- **离线**：对整段视频逐像素取**第 90 百分位**。一个目标只要停留时间不到全片的 90%，就不会被算进背景。
- **多段参考合并**：每段参考背景先用相位相关（基于通道壁的梯度）做亚像素对齐，再逐像素取最大值。只要某个像素在任意一段录像里露出过背景，就能得到正确的背景值。
- **实时**：从参考背景出发做慢速非对称更新。像素变亮时较快跟上（团离开后的位置很快恢复），变暗时极慢跟上（只跟随缓慢的光照漂移）；前景及其周边 6 像素不更新，所以停住的团不会被吸收。画面按行分成 10 条，每帧只更新其中一条，把计算量摊到每一帧。
- **后备方案**（实时模式且没有 `--ref`）：用第一帧当背景，并把其中"粗"的深色块（团）修补掉。通道壁是细线，团是粗块，大部分情况能区分开；但贴壁的团、壁上的缺陷会被误判，实验 B 里就出现了这种情况（见下文结果）。**仅作应急使用。**

### 2. 分割

1. 计算相对暗度 `D = 1 − I / B`（明场成像是乘性的，所以用除法），并减去每帧的中位数，以抵消整体亮度波动。
2. 滞后阈值：`D > lo` 的像素是候选；一个连通域中至少要有一个像素 `D > hi`，才会被保留。
3. 闭运算（约一个单泡直径）连接断开的边缘，只取外轮廓，相当于把团内部的亮孔填上。明场下单个微泡中心常有亮点，不填孔的话，团会碎成很多块。
4. 去掉面积小于 `min_area` 的连通域。

### 3. 关联（谁是谁）与事件

1. 把每条轨迹上一帧的掩膜按估计速度平移，看它落在当前帧的哪些连通域上（重叠像素数）。
2. 在重叠关系上用匈牙利算法确定一一对应的"延续"关系。
3. 剩下的重叠关系：
   - 两个及以上旧目标落在同一个新连通域上 → **融合**：面积最大的一方保留编号，其余编号结束，记录"并入"；
   - 一个旧目标落在两个及以上新连通域上 → **分裂**：最大的子块保留编号，其余子块获得新编号，并记录父编号。
4. 没有重叠的（小而快的单泡），再按预测位置的距离做一次匈牙利匹配，门限为 15 像素加上速度项。
5. 轨迹允许最多丢失 8 帧（被遮挡、短暂失焦），超时后结束；在画面边缘结束的记为 `exit`，在画面内结束的记为 `lost`。
6. **确认机制**：少于 5 帧的轨迹视为分割闪烁，连同涉及它的事件一起丢弃。实时使用时相当于约 80 ms 的确认延迟。

融合时让大的一方保留编号，是为了让团的位移轨迹不会因为吸收了一个小泡而中断；完整的谱系关系仍然记录在 `events.csv` 里。

## 参数

| 参数 | 默认值 | 含义 | 何时调整 |
|---|---|---|---|
| `--bg` | `offline` | `offline` 会读取整段视频估计背景；`online` 为实时模式，只用 `--ref` | 实时场景用 `online` |
| `--ref` | 无 | 同一次装片的其他视频或 `background.npy`，可给多个 | 实时模式务必提供 |
| `--lo` | 0.06 | 比背景暗 6% 以上算候选 | 背景噪声 σ≈0.004。降低能抓到更淡的目标，但会引入通道壁边缘碎点 |
| `--hi` | 0.12 | 连通域中至少有像素暗 12% 以上才保留 | 同上 |
| `--min-area` | 12 | 最小面积（像素） | 单泡在本视野约 15–30 像素 |
| `--percentile` | 90 | 背景分位数 | 有团几乎全程不动、又没有其他参考时，可以调到 95 |
| `--crop X Y W H` | 无 | 只处理画面的一部分 | 只关心某个区域，或需要进一步提速时 |
| `--fps` | 读视频 | 帧率 | 视频文件里记录的帧率不准时 |
| `--out` | `result` | 输出目录 | |
| `--render` | 关 | 另存叠加视频 `overlay.mp4` | |

跟踪相关的参数（重叠门限、最大丢失帧数、确认帧数等）在 `bubble_tracker.py` 的 `TrackParams` 里，一般不需要改。

## 输出文件格式

### `objects.csv`：每帧每个目标一行

| 列 | 单位 | 含义 |
|---|---|---|
| `frame` | 帧 | 帧号（从 0 开始） |
| `t` | s | 时间 = frame / fps |
| `id` | | 目标编号（按首次出现的顺序重新编号） |
| `cx`, `cy` | 像素 | 质心（图像坐标，y 向下） |
| `vx`, `vy` | 像素/帧 | 速度（指数平滑） |
| `area` | 像素 | 面积（团内部的亮孔已填上） |
| `eq_diam` | 像素 | 等面积圆直径 |
| `major`, `minor` | 像素 | 等效椭圆长轴、短轴（由二阶矩计算） |
| `angle` | 度 | 长轴方向，0–180° |
| `circularity` | | 圆度 4πA/P²，圆为 1，越不规则越小 |
| `solidity` | | 凸度 = 面积 / 凸包面积，团越"松散"越小 |

形状指标只对较大的团（面积大于约 200 像素）有意义，小目标上的值不可靠。

### `events.csv`：事件

| 类型 | `ids` | `result_id` | 含义 |
|---|---|---|---|
| `merge` | 被并入者 宿主 | 宿主 | 两个目标融合，宿主保留编号 |
| `split` | 父 新 | 父 | 从父目标分出一个新目标 |
| `appear` | 新 | 新 | 在画面内出现（如从失焦状态进入焦平面） |
| `enter` | 新 | 新 | 从画面边缘进入 |
| `lost` | 旧 | 旧 | 在画面内消失 |
| `exit` | 旧 | 旧 | 从画面边缘离开 |

另有 `frame`、`t`、`x`、`y`（事件发生位置）。

### 其他

- `background.npy`：本次使用的背景（float32，已做 σ=1 高斯模糊），可作为 `--ref`。
- `stats.json`：帧数、平均和 P95 每帧耗时（不含视频解码）、编号数、事件计数、所用参数。
- `overlay.mp4`：叠加视频。彩色轮廓是目标，细线是最近 1 秒的轨迹；顶部显示时间、当前目标数、累计编号数，以及最近 1.5 秒内的融合/分裂事件。
- `contours.npz`：每帧每个目标的外轮廓（加 `--save-contours` 时生成）。这只是额外输出，不改变任何计算结果：用同样参数加上这个选项重跑，`objects.csv` 和 `events.csv` 与不加时逐字节一致。

## 人工审查与数据清洗（review/）

自动追踪之后，由人逐条检查轨迹：把整条或其中一段标为 **Trusted（可信）/ Untrusted（不可信）/ Unreviewed（未检查）**，不可信的部分记录原因；同时把"同一个物体却被分成了几个编号"的情况合并起来。最后分别导出三类数据。不需要重画轮廓，也不需要逐帧标记；原始的 `objects.csv`、`events.csv` 永远不会被修改。界面是英文的。

### 启动

```bash
python review/review_tool.py --video data/raw/expA.mp4 --result results/A_offline
```

浏览器会自动打开 `http://127.0.0.1:8800`，按 Ctrl+C 退出。启动时会把整段视频解码进内存（22 秒的视频约 5 秒、65 MB）。`--video` 要给原始视频，不是 `overlay.mp4`。结果目录里需要有 `contours.npz`；没有的话，先用原来的命令加 `--save-contours` 重跑一次追踪（结果不会变）。同时审查两段视频时，第二个窗口加 `--port 8801`。结果目录里已有 `review.json` 时，会接着上次的进度继续。

### 界面

- **左侧有两个标签页。**
  - **Objects / Tracks**：列表有两种显示方式，用上方的 **By object / By ID** 切换（会记住上次的选择）。
    - **By object（默认）**：一个物体一行。合并过的几个编号收成一行，例如 `obj #83 ▸ 7 IDs`，点 `▸ 7 IDs` 可以展开各个成员编号；进度条覆盖整个物体的时间范围，编号之间的中断画成深色空档。**合并之后行数会相应减少**，标签页上的数字就是物体数。
    - **By ID**：一个编号一行，合并过的编号显示 `object #… · N IDs`。
    - 两种方式都可以按编号查找，按时长、面积过滤，按状态筛选（Has unreviewed parts / Has untrusted parts / Fully reviewed / Made of several IDs），也可以排序，例如 By wall contact，优先检查贴壁的团。按 `[` / `]` 时，By object 下按物体切换，By ID 下按编号切换。
  - **Same-object suggestions**：程序自动找出的"疑似同一物体"编号对，详见下文"同一物体被分成多个编号"。
- **中间：画面。**
  - 选中的轨迹用黄色实线高亮，画出它最近 1.5 秒的路线；
  - 同一物体的其他编号用黄色虚线，正在查看的建议编号用青色虚线；
  - 其他目标按审查状态着色：白 = 未检查，绿 = 可信，红 = 不可信；
  - 直接点击画面上的目标就能选中它；
  - 勾选 **Follow & zoom** 后，画面放大 3 倍并跟着目标走。
- **时间轴。**
  - 一个物体的所有编号画在同一条轨道上：当前编号用黄框，其他编号用虚线框；
  - 蓝线表示接触通道壁或杂质；紫色 ▼ 是融合，青色 ▲ 是分裂，橙色竖线是提示；
  - 点击跳转，拖动选择时间段；用 **This object / Whole video** 切换显示范围。
- **右侧：操作面板。** 轨迹信息、**Same object**（本物体包含的编号、手动合并、拆开、针对本物体的建议）、**Select a range**、三个判断按钮、Reason（8 种预设原因）和 Note、Marked ranges（已标注的时间段，可重新选中或清除）、Hints。

典型操作：选一条轨迹 → 播放或逐帧看 → 在时间轴上拖出一段（或用 I / O 设起点、终点）→ 按 T / U / C → 按 `]` 进入下一条。

| 快捷键 | 作用 | 快捷键 | 作用 |
|---|---|---|---|
| Space | 播放 / 暂停 | I / O | 起点 / 终点 = 当前帧 |
| ← / → | 前后 1 帧 | A | 选择整条轨迹 |
| Shift + ← / → | 前后 10 帧 | T / U / C | Trusted / Untrusted / 改回 Unreviewed |
| Home / End | 跳到轨迹首 / 尾 | [ / ] | 上一条 / 下一条轨迹 |
| Z | 跟随放大 | Ctrl + Z | 撤销（标注、合并、拆开、忽略建议都能撤销） |

勾选 **Loop selected range** 时，播放会在所选时间段内循环。

### 同一物体被分成多个编号

**为什么会这样。** 颜色较淡、几乎不动的小目标，暗度常常正好卡在检测门槛（核心暗 12%）上下。略低于门槛时，它就会短暂"消失"；消失超过 8 帧后再出现，追踪程序会给它一个新编号。例如实验 A 中的 #103、#107、#111，其实是位于 (459, 644) 的同一个约 40 像素的小目标：
- 第 1091 到 1105 帧被检测到；
- 中间断了 49 帧，然后第 1155 到 1181 帧再次出现；
- 又断了 15 帧，从第 1197 帧起再次出现。

在 A 中这种情况约有 18 个物体、涉及 64 个编号；B 中约 9 个物体、涉及 23 个编号。

**自动建议。** 一个编号结束后，如果另一个编号在 5 秒（300 帧）内、在几乎同一个位置（距离 ≤ 12 像素，也会按它结束前的速度推算位置）出现，并且面积相差不超过 2.5 倍，就列为建议。每个编号最多出现在一条建议里。已经合并的物体只能在两端继续接上新编号。

**操作：**
1. 在 Same-object suggestions 里点 **Show**：选中前一个编号，并跳到它结束前约半秒，方便播放着看过中断；
2. 确认是同一物体就点 **Link**，不是就点 **Not same**（之后不再提示这一对）；
3. 也可以在右侧 **Same object** 里直接输入编号（如 `107, 111`）合并，或者用 **Unlink** 把某个编号拆出来。

**合并后：**
- 时间轴、画面和路线显示整个物体的完整过程；
- **Whole object** 按钮可以选中这个物体的全部时间；
- 勾选 **Apply to all linked IDs of this object** 时，一次标注会作用到所选时间段内的每个编号。

**限制：** 在同一帧里同时存在的两个编号不能合并，程序会拒绝并说明原因。合并后，物体编号（`object_id`）取组内最小的编号。

### 提示和"接触通道壁或杂质"

**提示**（Hints）是自动给出的，用来帮你快速找到值得看的地方，但不代表一定出错。真实的快速移动、变形，或者团连在一起，都可能触发提示。包括以下几类：
- 位置一帧内跳变超过 8 像素，且超过这条轨迹平时每帧移动距离的 5 倍；
- 面积一帧内变化超过约 30%（只对 50 像素以上的目标）；
- 中断几帧后又接回；
- 开始接触通道壁或杂质；
- 融合与分裂。

**接触通道壁或杂质**的判断方法：在背景里取比周围暗 6% 以上的静止结构（通道壁、固定杂质），向外扩 2 个像素；目标轮廓和它重叠 3 个像素以上，就算接触。实验 A 中约 70% 的目标帧满足这个条件，因为团和微泡常被超声推到壁上。贴壁时面积会偏小（见"已知局限"）。

### 保存的文件

每次操作都会立即写入结果目录：

| 文件 | 内容 |
|---|---|
| `review.json` | 全部人工判断：标注段（轨迹编号、起止帧含两端、状态、原因、备注）、同一物体的合并组（`links`）、标为"不是同一物体"的编号对（`dismissed`），以及完整的修改记录 |
| `trusted.csv` | 可信的目标帧 |
| `untrusted.csv` | 不可信的目标帧（含原因、备注） |
| `unreviewed.csv` | 还没检查的目标帧 |
| `objects_reviewed.csv` | 全部目标帧，加审查状态列 |
| `events_reviewed.csv` | 事件表，加 `review_status` 和 `object_ids`（事件涉及的物体编号） |
| `review_report.txt` | 导出核对报告 |
| `review_overlay.mp4` | 核对视频（按 **Make check video** 后才有）：绿 = 可信，红 = 不可信，灰 = 未检查；标签格式为 `#物体(轨迹)` |

几点规则：
- **CSV 的列。** 前几列与原始 `objects.csv` 完全相同，后面加了 `review_status`、`review_reason`、`review_note`、`touches_static`（是否接触通道壁或杂质）和 `object_id`（合并后的物体编号；没合并的就等于自身编号）。**做单个物体的位移和形变分析时，按 `object_id` 分组。**
- **时间段不会重叠。** 同一条轨迹上，后标的时间段会覆盖先标的重叠部分。
- **事件的审查状态。** 事件涉及的轨迹在事件时刻都可信，事件才算可信；任何一条不可信，事件就算不可信；其余算未检查。
- **Export & check 会检查六件事：** 三类文件的行数之和等于原始行数；每一行都与原始 `objects.csv` 完全一致；没有任何一行同时出现在两类里；`objects.csv` 在审查期间没有被改动；所有标注段都在轨迹的存在范围内；合并组里没有时间重叠的编号。
- **只导出、不开界面：** `python review/review_tool.py --video ... --result ... --export --render`
- **兼容旧版。** 旧版工具保存的 `review.json` 可以直接读入，已有标注保留。旧版的原因是中文的，会原样保留。

### 用这些数据时注意

- `trusted.csv` 按 `object_id` 分组后，适合做单个微团的位移和形变分析。
- 整个视野的聚集与分散统计，不能只用可信轨迹，否则被排除的目标会让分布产生偏差。应该用 `objects_reviewed.csv` 里的全部目标帧来统计，再按审查状态做对照，比如去掉不可信的部分后，结论是否改变。
- 如果之后重新运行了追踪，`objects.csv` 变了，原来的 `review.json` 就对不上了。工具启动时会提示版本不一致。

## 第二轮：位移、形变与聚集/分散（analysis/）

这一轮把第一轮审查过的轨迹，变成描述"微团怎么移动、怎么变形、整个微泡群体怎么聚集或分散"的数字和曲线。

- 只读取已有结果，不改追踪算法，也不改 `objects.csv`、`events.csv`、`review.json` 等任何已有文件。
- 结果全部写进结果目录下新建的 `analysis/` 文件夹。

### 运行

```bash
python analysis/analyze.py --result results/A_offline --video data/raw/expA.mp4   # 计算全部表格、图和核对图，约 30 秒
python analysis/viewer.py  --result results/A_offline --video data/raw/expA.mp4   # 打开曲线与视频对照的网页
```

可选参数：

| 参数 | 作用 |
|---|---|
| `--video` | 只用于生成关键时刻核对图和视频对照自检；不给也能算出全部表格和曲线 |
| `--um-per-px 0.65` | 知道显微镜标定后加上。所有长度、面积、速度会多出一列微米单位（`_um`、`_um2`、`_um_s`） |
| `--fps 1000` | 相机实际录制帧率与视频播放帧率不同时（例如高速录制、按 60 fps 导出），用真实帧率换算时间和速度 |
| `--exclude-reason "..."` | 哪些"不可信原因"表示确认不是微泡。默认只有 `Not a bubble (debris or artifact)` |

浏览器会自动打开 `http://127.0.0.1:8810`，可以和审查工具（8800）同时开。

### 任务 1：整理可信数据（`segments.csv`）

只取第一轮标为 Trusted 的目标帧，把每个编号连续的可信部分切成一段"可信片段"（segment）。遇到下面两种情况就切开：

- 中间有不可信或未检查的部分；
- 这个区域和别的区域在图像上连成一片，或者有区域从它身上分出去（追踪程序的 merge / split 事件）。连通前后已经不是同一个东西，不能当成同一个团的连续变形。

片段之间**不会自动连接**。第一轮判为同一物体的几个编号也不连接，`object_id` 只用来把它们归到同一物体、画在同一张图里。

每段记录：

- 起止帧，以及开始原因：视频开头、进入视野、出现、与 #x 连通、#x 分出之后、前面是不可信部分；
- 结束原因：视频结束、离开视野、消失、连入 #x、后面是不可信部分；
- 这一段的位移、速度和形状摘要。

"进入视野 / 离开视野"按轮廓判断：第一帧（或最后一帧）的轮廓碰到画面边缘，或者按当时的速度往前（往后）推 3 帧会碰到边缘。

不可信和未检查的数据没有删除。它们仍在第一轮的 `untrusted.csv`、`unreviewed.csv` 里，也带着审查状态出现在 `state.csv` 里。

### 任务 2：位移和速度（`motion.csv`）

- **位置**：区域中心 `x_px, y_px`。原点在画面左上角，x 向右，y 向下。
- **位移**：`dx, dy, disp` 是相对该片段第一帧的位置变化；`path` 是沿途累计走过的路程。
- **速度**：用原始位置和真实时间重新计算，不用 `objects.csv` 里的 `vx, vy`（那是平滑过的"像素/帧"，有滞后）。做法是取前后各 0.05 秒（3 帧）的位置差，除以时间差；片段开头和结尾只用一侧。
- **方向** `direction_deg`：0° = 向右，90° = 画面上方，180° = 向左，−90° = 画面下方。
- `at_image_edge = 1`：区域被画面边缘截断，中心只代表可见部分，这几帧的速度要谨慎看。

### 任务 3：形变（`shape.csv`）

| 列 | 含义 |
|---|---|
| `area_px2` | 可见面积 |
| `aspect_ratio` | 长轴 / 短轴。1 = 圆，越大越细长 |
| `circularity` | 圆度 = 4π × 面积 / 周长²。越接近 1 越圆、越光滑 |
| `solidity` | 凸度 = 面积 / 凸包面积。1 = 没有凹陷 |
| `orientation_deg` | 长轴方向，0–180°，从水平方向逆时针量 |
| `orientation_unwrapped_deg` | 把 179° → 1° 这样的跳变接起来，用来计算转了多少度 |
| `area_rel_start` | 相对片段第一帧的面积 |
| `edge_on_wall` | 轮廓落在通道壁或固定杂质上的比例（0–1） |

每一帧都有 `shape_quality`：

- `good`：可以直接用；
- `wall contact`：轮廓超过 20% 的长度落在通道壁或固定杂质上。区域是真实的，位置可用；但贴壁那一侧的形状由壁决定，面积可能偏小；
- `poor`：面积小于 200 像素²（约 16 像素宽，形状数字太粗），或者被画面边缘截断。

`orientation_ok`：只有形状为 good、且长宽比 ≥ 1.2 时，方向才有意义。

真实的快速变化不会因为曲线突然跳动而被删除。

### 任务 4：整个视野（`collective.csv`、`field_events.csv`）

这里用的是**全部检测**，不只是可信轨迹。每个区域按第一轮的审查结果分三类：

- **可信**：正常统计；
- **确认的假目标**（不可信，原因为 "Not a bubble"）：不统计；
- **不确定**（未检查，或不可信但原因不是"不是微泡"）：照常统计，但单独计数。不确定区域占可见面积超过 5% 的帧，`field_quality` 标为 `uncertain`。

每帧的指标：

| 列 | 含义 | 用来看 |
|---|---|---|
| `n_regions` / `n_confirmed` | 可见区域数 / 其中可信的 | 区域在连成团（变少），还是在散开（变多） |
| `total_area_px2` | 可见总面积 | |
| `centroid_x_px, centroid_y_px` | 按面积加权的整体中心 | 整个群体往哪移动 |
| `spread_px` | 各区域离整体中心的距离（按面积加权的均方根） | 越小越集中 |
| `hull_area_px2` | 能包住全部区域的最小凸多边形面积 | 分布范围 |
| `cluster_area_share` | 面积 ≥ 300 像素² 的团占总面积的比例 | 有多少微泡已经在团里 |
| `largest_share` | 最大区域占总面积的比例 | 是否形成一个主导的大团 |
| `nn_gap_median_px` | 每个区域到最近另一个区域的边到边距离，取中位数 | 区域之间是否在靠近 |
| `mean_center_dist_px` | 两两中心距离的平均值 | |
| `connect_events` 等 | 这一帧发生的连通 / 分开 / 进入视野 / 离开视野次数 | |

`field_events.csv` 列出每一次事件。"连通"只表示两个区域在图像上连成了一片，不直接等于物理融合。

区域进入或离开视野时，整体指标也会跳变。这些时刻单独列为 `enter view` / `leave view`，图上也有标记。和它们同时发生的跳变是视野变化造成的，不是聚集或分散。

### 任务 5：图表和核对

**图（`figures/`）**

| 文件 | 内容 |
|---|---|
| `trajectories.png` | 全部可信片段画在背景上，主要物体用彩色 |
| `motion_summary.png` | 主要物体离起点的距离、速度 |
| `shape_summary.png` | 主要物体的面积、长宽比 |
| `collective.png` | 整个视野的全部指标和事件 |
| `objects/object_<编号>.png` | 每个主要物体一张：路线、位置、速度、面积、长宽比、圆度、凸度、方向 |

主要物体 = 可信期间达到团的大小（≥ 300 像素²），并且可信时间累计 ≥ 1 秒。实验 A 有 10 个。

**核对图（`checks/check_*.png`）**

程序自动挑出几个最值得核对的时刻，把前、中、后三帧画面和曲线并排放，方便用肉眼判断曲线是否反映了视频里的真实变化。挑选的时刻包括：

- 主要物体面积变化最大的时候；
- 一次连通事件；
- 主要物体运动最快的时候；
- 整个视野的总面积、团占比、分布范围变化最大的时候。

**对照网页（`viewer.py`，英文界面）**

- 左边选一个物体，或者 "All regions"（整个视野）；中间是视频，右边是曲线。
- **在曲线上点一下，就跳到那一帧。**
- 顶部 **Key moments** 可以直接跳到核对图对应的时刻。
- 画面上的轮廓颜色：黄色 = 选中的物体，绿色 = 可信，橙色 = 不确定，红色 = 假目标。

**同时开始运动（`onsets.csv`）**

`onsets.csv` 记录每段可信轨迹从静止开始运动的时刻：先连续 0.3 秒低于 10 像素/秒，然后超过这个速度，并在 0.2 秒内超过 30 像素/秒。如果 0.1 秒内有 3 个以上物体同时开始运动，就写进 `report.json` 的 `joint_motion_starts`，图中用黄色竖带标出。这些时刻很可能对应驱动发生了变化，第三轮可以直接拿它们和 PZT 动作记录对照。

### `state.csv`：统一的状态记录

每帧每个区域一行，包括不可信和未检查的区域。每一行把下面这些放在一起：

- 审查状态和所在片段；
- 位置、速度、形状；
- 这一帧整个视野的指标；
- 数据可信度。

第三轮只要按帧号把 PZT 动作合并进来，就能得到"当前状态 + 动作 → 下一刻状态"的实验记录。

### `report.json`：参数、自检和数据质量说明

包含全部参数、输入文件的 SHA1、主要物体列表、整个视野摘要、同时开始运动的时刻、核对图清单，以及下面这些自检（`all_checks_passed`）：

1. 运动和形状只用了可信行，行数与可信行数一致；
2. 每个可信行恰好属于一个片段；
3. 没有片段跨过连通 / 分开事件；
4. 每个片段只含一个编号；
5. 重新计算的速度与追踪程序的速度一致；
6. 整个视野统计了除假目标以外的全部区域；
7. `review.json` 对应当前的 `objects.csv`；
8. 审查状态与第一轮导出的 `objects_reviewed.csv` 一致；
9. 分析前后输入文件没有变化；
10. **与原始视频对照**（给了 `--video` 时）：随机抽 100 个主要物体的帧，不经过分割，直接在视频上做模板匹配，测量 0.1 秒内的位移，与曲线比较。

`data_quality` 里是需要注意的地方，例如没有填原因的不可信段、形状质量的分布、片段结束原因的统计。

### 实验 A 的结果

**基本数字**

- 118 个编号 → 67 个物体，111 段可信片段，10 个主要物体。
- 10 项自检全部通过。
- 与原始视频对照：在 0.1 秒、最大约 69 像素的位移上，曲线与模板匹配的中位差为 0.32 像素，相关系数 0.998。
- 团（≥ 300 像素²）的可信帧中：good 31%，wall contact 68%，poor 1%。团大部分时间压在通道壁上，这些时段的面积和长宽比要谨慎解读。

**整个视野**

- 第一秒 → 最后一秒：
  - 区域数 20 → 14；
  - 总面积 9980 → 6280 像素²；
  - spread 183 → 217 像素；
  - 团占总面积 87% → 84%。
- 事件：20 次连通，13 次分开，6 次进入视野，5 次离开视野。

**从曲线和核对图看到的几个时刻**（第三轮需要与 PZT 动作时间对照）：

1. **3.07 s：16 个物体在第 184–185 帧（前后相差 1 帧，约 17 ms）同时开始运动。** 另外两次同时开始运动在 6.05 s（4 个物体）和 12.08 s（5 个物体）。
2. **3.1–4.8 s：团压实、连通。**
   - #11 开始移动后 0.25 秒内，面积从约 4500 降到 3200 像素²，画面上可以看到团变得更紧实（`check_01`）。
   - 随后 #8、#6 等依次与 #11 连通。
   - 整个视野的可见总面积从约 9900 降到约 5300 像素²。一部分来自团压实，一部分来自团贴到了壁上：这段时间之后，#11 大多是 wall contact。
3. **6.28 s：#53 从右分支下方高速进入视野。**
   - 进入时约 900 像素/秒，0.4 秒内减速到约 100 像素/秒（`check_04`）。
   - 团占面积比例随之跳升，这是视野变化（`check_06`）。
4. **12.1 s：#11 从左分支的壁上脱离。**
   - 0.35 秒内移动约 140 像素，最快约 690 像素/秒，面积几乎不变（`object_11.png`）。
   - 13.9 s 从画面下方离开；几乎同时，#78 从上方进入（13.7 s）。spread 在 13.8 s 的尖峰就是这两件事造成的（`check_07`）。

**需要确认的两处审查**

#13（帧 1040–1091）和 #14（帧 0–771）标了不可信，但没有写原因，目前按"不确定"计入整个视野。其中 #13 在 18.18 s 变成一段约 1300 像素²的通道壁，在总面积曲线上造成一个尖峰。如果它们不是微泡，在审查工具里补上原因 "Not a bubble"，再运行一次 `analyze.py`。

实验 B 还没有人工审查，所以没有生成第二轮结果。审查完成后，用同样的命令运行即可。

### 第二轮的局限

- **位置是区域的中心。** 区域被壁遮住一部分、与别的区域连通或分开时，中心也会移动。连通和分开处已经切段；贴壁只做了标记（`edge_on_wall`），没有修正。
- **速度是图像里可见区域的速度，不等于液体流速；面积变化也不等于受力大小。** 两者之间的关系需要结合物理模拟和实验测量。
- **单位。** 没有 `--um-per-px` 时，全部是像素和秒。
- **阈值是固定的。** 200 像素²、20%、300 像素²、10 / 30 像素/秒等阈值写在 `analyze.py` 开头的 `DEFAULTS` 里，并且全部记录在 `report.json`；改动后重跑即可。

### 与基准的一致性（`results/comparison.md`）

| 被测 | 小目标检出率 | 小目标准确率 | 团检出率 | 团准确率 | 每帧团总面积（基准 → 被测，像素） |
|---|---|---|---|---|---|
| A_online | 98.6% | 99.4% | 100% | 100% | 5038 → 5073 |
| A_offline_noref | 97.7% | 99.5% | 99.9% | 100% | 5038 → 4920 |
| B_online | 99.3% | 99.9% | 100% | 100% | 4659 → 4657 |

| B_online_firstframe | 68.2% | 85.8% | 59.3% | **47.5%** | 4659 → **8353** |

### 结论

1. **只要有参考背景，实时模式和离线结果几乎一致**：团的检出率和准确率都是 100%，团面积相差不到 1%，每帧约 15 ms，可以跟上 60 fps。
2. **团长时间不动时，需要其他录像参与估计背景。** 实验 B 的团几乎全程停在原地，只用 B 自己估计背景时，团的一部分会被当成背景：团面积少了约 4.5%，小目标检出率降到 85.8%。探索阶段还测过不同分位数下被吸收进背景的面积：第 75 百分位约 1580 像素，第 90 百分位约 350 像素，再与 A 的背景合并后基本为 0。
3. **只用第一帧当背景不可行。** 右分支内侧通道壁上有一处缺陷，形状像团，被误判后整段壁都被当成了目标，团准确率只有 47.5%。可以在 `results/B_online_firstframe/overlay.mp4` 里看到。
4. **一个值得验证的现象**：两次实验里，几个团都在同一时刻出现面积突变（A 约 3.3 s，B 约 4.2 s），并且同时开始移动；B 的两个团都是朝通道壁方向移动（见 `results/figures/`）。这很可能对应 PZT 状态切换。面积变小可能是团被压实了，也可能是贴壁后被壁遮住的部分没有计入面积，需要和 PZT 的时间记录对照才能确定。

## 已知局限

- **视频是压缩过的。** 两段"原始"视频是相机导出的 H.264（约 5 Mbps）。现在的画质已经够用；如果相机支持无损或更高码率的格式，边缘会更干净。
- **贴壁团的面积会偏小。** 团压在通道壁上时，与壁重叠的那部分像素本来就暗，不会被计为前景。实验 A 中约 70% 的目标帧接触通道壁或杂质，`touches_static` 列可以用来区分。
- **小单泡会时隐时现。** 单个微泡在焦平面上下移动时会出现、消失，这是物理原因，二维跟踪无法消除，体现为较多的 `appear` 和 `lost` 事件。
- **形状指标的适用范围。** 圆度和凸度只对大于约 200 像素的团有意义（第二轮里面积小于 200 像素²的帧形状质量记为 poor）。
- **耗时不含取帧。** `stats.json` 里的耗时只包括分割和跟踪，不包括视频解码或相机采集。在 2 核云端虚拟机上测得的数字，一般电脑会更快。
- **只用第一帧当背景不可靠。** 务必在实时模式下提供 `--ref`。

## 后续可做

- **像素换算**：已支持，运行 `analyze.py` 时加 `--um-per-px`。
